# CosenseからCSP原稿を作成

対象のMacにあるCLIP STUDIO PAINT EXをComputer Useで操作する。本文の解釈には既存のcosense-to-clipstudio変換結果を使う。これは操作手順であり、CSPを直接制御するプログラムではない。

## 入力と前提

- 入力はCosense URLまたはmanifest JSON。作品名、保存先、プリセット、綴じ方向・開始側・見開き設定、コマ枠テンプレートはユーザー指定または明示的に保存された作品設定を使う。実行に不可欠な設定だけ、不明なら確認する。
- ページ管理作品にはEXが必要。利用可能なComputer Use接続、原稿保存先へのアクセス、必要ならCosenseのログインとUserScriptを確認する。操作環境がなければ原稿が作成できたとは報告しない。
- Mac版EX 5.1.4で部分検証済み。他のOS・版、無人での通し実行は未検証。検証条件と集英社設定例は [references/verified-profile.md](references/verified-profile.md) を必要時に読む。
- 新規作品は既存原稿を上書きしない。再開では実行記録にある作品だけを継続する。同じCSPを複数タスクから同時操作しない。

## 1. manifestとページ計画

1. 指定ページの既存UserScriptで「CLIPSTUDIO用に出力」→「Computer Use用JSONを書き出す」を使い、manifestを作業フォルダに保存する。コピーまたは入力済みJSONでもよい。プロット変更後はモーダルを開き直す。関連ページを混ぜない。
2. 本文取得用の接続が利用できる場合は、ユーザーが指定したリポジトリの変換処理を使う方法でもよい。LLMで括弧記法を再解釈したり、セリフを作り直したりしない。リポジトリは固定パスにあると仮定しない。
3. `schema: cosense-to-clipstudio/manifest`、`version: 1` を確認する。`pageCount` はセクション数で物理ページ数ではない。各 `number` / `endNumber`（省略時はnumber）の範囲を検証し、連続したページ構成から物理ページ数を決める。
4. `warnings` はページ別・全体の両方、`notes` は存在すれば読む。欠番、重複、逆順、範囲重複、見開き設定との不一致を勝手に補正しない。`documentSettings.pageCount` があれば物理ページ数と照合する。構成が決められなければ作成前に確認する。
5. 番号、label、kind、text、sourceLine、warnings、notesを保持する。見開き項目は一度だけ配置し、空のitemsを持つページも保持する。先頭・末尾に白紙や表紙を自動追加しない。
6. トップレベルに `fullWidth: true` があれば、本文の半角英数字（`0-9` `A-Z` `a-z`）はUserScript側で全角化済みなので、そのまま貼り付ける。無ければ本文は元のままで、全角化はユーザー指定がある場合だけ行う。どちらの場合も記号・空白・二桁数字の縦中横には手を加えない。

## 2. 原稿作成と文字入力

CSP操作前に [references/csp-operation.md](references/csp-operation.md) を読む。

- 指定プリセット・ページ数・綴じ方向・開始側・見開き・テンプレートでcmc管理作品を作る。まずページ管理画面でページの組み合わせとコマ枠を確認する。素材がなければ類似素材で黙って代用しない。
- 1抽出項目につき1つの編集可能な文字レイヤーを作る。各キャンバスのルート直下の「テキスト」フォルダへまとめ、コマ枠フォルダの子にはしない。
- 単ページ由来の本文は正しい側に置く。本文順を維持し、対応するページ内に収める。指定がなければ既定書体を使い、細かなレイアウト調整はしない。kindだけで書体や吹き出し図形が自動適用されるとは扱わない。
- 一連の確定操作をまとめ、画面の変化に応じて確認する。古い座標の再生はしない。キャンバスごとに保存する。

## 3. 保存・再開・検証

各作品の作業フォルダに、manifestと実行記録（JSON等）を置く。スキルの配布フォルダには原稿や実行記録を保存しない。

記録する項目：元URL、manifestの版を識別できるハッシュ等、作品設定、cmc保存先、ページとclipの対応、セクションと項目の位置・sourceLine・kind・レイヤー名、投入済み/保存済み/確認済みの状態、停止理由。sourceLineは複数項目で共通になり得るため単独の識別子にしない。

再開時は記録と現在の原稿を照合する。実行済み項目を再投入しない。元プロットが変わっていたら変更範囲を確認し、作画中原稿へ自動的に全面反映しない。

全ページの構成・枠、項目数・本文・配置先、独立レイヤーと親フォルダ、保存を確認する。可能ならCSPからテキストを書き出して照合する。確認できない項目は未確認と記録する。同じ原因の失敗が2回続いたら再試行を止め、保存済み範囲と必要な対応を報告する。

完了報告には保存先、物理ページ数、文字レイヤー数、検証結果と残った警告を含める。タスク終了だけで原稿完成と判定しない。

## dots等からの引き継ぎ

実行先のMac、入力manifestまたはURL、作品設定、保存先、本スキルの場所、再開記録を実行タスクへ渡す。別タスクが過去の会話をすべて読めるとは仮定しない。ローカル実行環境への接続は別途必要。原稿作成とスキル開発を同時に行わず、改善案は次回用に記録する。
